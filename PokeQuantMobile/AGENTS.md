# PokeQuantMobile Agent Rules

PokeQuantMobile is the offline-first Expo / React Native companion to the PokeQuant vendor trading terminal. It keeps a local `expo-sqlite` database (`pokequant.db`) on the device and syncs inventory rows to the same multi-tenant Turso cloud database used by the PokeQuant PWA, routed through the Cloudflare Worker edge proxy.

## Monorepo Isolation

When working on the mobile app, your scope is strictly confined to the `PokeQuantMobile/` directory. Do not modify files in the monorepo root (`app.py`, `sw.js`, `card_tool.py`, `index.html`, `worker.js`, `AGENTS.md`, `global_rules.md`, etc.). If a mobile task requires shared cloud or web infrastructure, surface the dependency to the user instead of editing root files.

## System Architecture

- **Frontend / Runtime:** React Native 0.81.5 + Expo 54, written in TypeScript. Entry points are `index.ts` and `App.tsx`.
- **Navigation:** React Navigation bottom-tabs in `src/navigation/AppNavigator.tsx` (Home, Search & Buy, Inventory, Settings).
- **State Management:** React Context providers in `src/context/` (`Auth`, `VendorSettings`, `Inventory`, `Cart`).
- **Local Database:** `expo-sqlite` in `src/db/database.ts`, `src/db/inventoryDb.ts`, and `src/db/syncDb.ts`. Database name is `pokequant.db`.
- **Cloud Sync:** `src/api/cloudSync.ts` sends batched `INSERT OR REPLACE` statements to the Cloudflare Worker at `CLOUDFLARE_WORKER_URL`, authenticated by `X-Beta-Key: userId`.
- **UI / Theme:** Strict dark theme defined in `src/constants/colors.ts` (`background: #0e1117`, `surface: #161b22`, etc.).

## Database Schema & Data Logic

Local SQLite (`pokequant.db`) and cloud `inventory` mirror the PokeQuant PWA schema:

- `cards`: `product_id` (INTEGER PK), `card_name`, `card_number`, `set_name`, `rarity`, `image_base64`
- `price_history`: `product_id`, `sub_type`, `date`, `market_price`. PK is `(product_id, sub_type, date)`.
- `inventory`: `id` (TEXT PK), `user_id`, `product_id` (INTEGER), `card_name`, `card_number`, `set_name`, `variant`, `condition`, `purchase_price`, `sticker_price`, `date_bought`, `is_bulk_deal`, `is_sold`, `sold_price`, `date_sold`, `custom_image_data`, `is_deleted`, `updated_at`.
- `vendor_settings`: `user_id` (PK), `settings_json`, `updated_at`.
- `tour_state`: `user_id` (PK), `has_seen_tour`.
- `sync_metadata`: `user_id` (PK), `last_updated`.

Data rules:

- `inventory.id` is a UUID hex string generated by `expo-crypto.randomUUID().replace(/-/g, '')` (`src/db/database.ts`). The local and cloud `inventory` tables must use `id TEXT PRIMARY KEY`.
- Synchronization is Last-Write-Wins by Unix timestamp (`updated_at`) with soft deletes (`is_deleted = 1`).
- `product_id` is an INTEGER. When building CDN image URLs or passing to the worker, explicitly cast to `int` to avoid float/string mismatch.
- Buy tiers in `VendorSettingsContext` compute cash offers as `marketPrice * marginPercent / 100`.
- Sticker rules (`roundingMethod`, `cutoff`, `minSticker`) round and floor sticker prices via `getStickerPrice()`.
- Search normalization must strip apostrophes, hyphens, and periods before matching (e.g., matching `Farfetch'd` or `M-Gardevoir-EX`).
- `custom_image_data` is a JSON string holding extra fields (`liveMarket`, `imageUrl`, `productType`) because the mobile table keeps the same column layout as the cloud schema.

## Agent Rules & Boundaries

### UI Thread Performance
Never block the React Native JavaScript thread with long synchronous work. Heavy inventory loads, price calculations, and catalog hydration must:
- Run in small chunks (50-100 items at a time).
- Use `setTimeout`, `requestAnimationFrame`, or async effects, not inline during render.
- Avoid re-triggering `useEffect` cleanups during navigation.

### No Web / Pyodide / PWA Patterns
The Expo app is a native iOS/Android build. Do not use WebAssembly, IndexedDB, Pyodide, browser Service Workers, Streamlit, `st.session_state`, `st.rerun`, `st.popover`, Pandas, or PyArrow. Use Expo and React Native primitives for storage, networking, and rendering.

### SQLite & Persistence
- All local persistence uses `expo-sqlite`. Use `database.withTransactionAsync()` for multi-row writes.
- The `inventory.id` column is `TEXT PRIMARY KEY` (`src/db/database.ts`). Never change it to an `INTEGER PRIMARY KEY` rowid alias or cloud sync will throw `datatype mismatch`.
- Keep database access asynchronous; do not run SQL on the render thread.

### Cloud Sync Safety
- `pushPendingInventoryChanges` (`src/api/cloudSync.ts`) sends chunks of `SYNC_BATCH_SIZE` (500) rows.
- It validates SQL placeholder / argument counts in `buildInventoryStatement` and throws `SyncFatalError` on mismatch.
- Fatal Turso / SQLite error patterns: `datatype mismatch`, `syntax error`, `wrong number of arguments`, `no such table`, `no such column`, `constraint failed`, `unique constraint failed`.
- `SyncButton` surfaces a "Clear Stuck Queue" alert when `syncFatalError` is set, which calls `clearPendingSyncs`. Do not auto-flush the queue.
- Tenant isolation: every Worker request must include `X-Beta-Key: userId`. Never sync without the current `userId` from `AuthContext`.
- Pending sync count is defined as rows where `updated_at > sync_metadata.last_updated`.

### UI & Rendering
- Use `FlatList` with `pagingEnabled` and `snapToInterval` / `snapToAlignment` for horizontal carousels.
- Paginate unbounded lists: the Active Inventory floating-card carousel uses 4 cards per page; the Completed Sales stream uses `STREAM_PAGE_SIZE = 6`; Performance chart carousel pages one chart at a time.
- Use modals / bottom sheets for per-card actions, not hidden conditional popovers. `InventoryScreen` uses `EditAssetModal`.
- Keep component trees shallow; use `React.memo` and `useMemo` for expensive inventory rows and price calculations.
- All numeric inputs are controlled React Native `TextInput` with strict parsing (`Number.parseFloat`, `Number.isNaN`). Do not mirror `st.number_input`.
- Use `NumericStepper` for settings that need stepped numeric values.

### Theme
- Background `#0e1117`; surfaces `#161b22` / `#1f242c`; borders `#30363d`; primary `#3b82f6`; text `#c9d1d9`; muted `#8b949e`; success `#22c55e`; error `#ef4444`.
- Avoid pure-white backgrounds and light gray page surfaces; keep shadows subtle for dark mode.

### State Conventions
- `AuthContext`: `userId`, `isLoggedIn`, `login`, `logout`.
- `VendorSettingsContext`: buy tiers, `stickerRules`, `getCashOffer`, `getStickerPrice`, tour state.
- `InventoryContext`: active inventory, completed sales, pending sync count, `triggerSync`, `clearPendingSyncs`, add/update/remove/sell/undo.
- `CartContext`: in-memory lot cart used by `SearchBuyScreen` and `CartDrawer`.

### Catalog & Market Data
- `SearchBuyScreen` currently uses `DUMMY_CARDS` for UI development. Do not replace it with live scraping or catalog hydration without coordinating with the shared cloud catalog pipeline.
- Use lightweight 1/3/7/30-day windows for search velocities and market watch. Avoid loading full 90-day price history on the JS thread unless requested.

## Verification

After `npm install`, `node` and `npm` may not be on the system `PATH`. Run the TypeScript type checker from `PokeQuantMobile/` with:

```powershell
& "C:\Program Files\nodejs\node.exe" node_modules\typescript\bin\tsc --noEmit
```

## Tooling Notes

- On Windows, invoke the type checker with the full `node.exe` path as shown above.
- Do not add new runtime dependencies without updating `package.json` and checking Expo SDK compatibility.
- Git commit messages should be a single line: `git commit -m "message"`. Avoid multi-line Devin-generated signature blocks or `Co-Authored-By` trailers.
